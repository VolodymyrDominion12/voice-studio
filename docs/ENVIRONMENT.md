# Середовище: що реально є на цій машині

Перевірено командами на `volodymyr@` (Ubuntu 24.04.5 LTS, bare metal).
Дата перевірки: момент створення цього документа.

## Апаратне забезпечення

| Компонент | Факт | Наслідок для проєкту |
|---|---|---|
| CPU | 8 ядер | Основний шлях інференсу — CPU. Восьми ядер досить для Piper і Kokoro. |
| RAM | 19 GiB (≈11 GiB вільно) | Вистачає для CPU-інференсу і для завантаження моделей у RAM. Не вистачить, щоб тримати кілька великих моделей одночасно. |
| GPU | **NVIDIA GeForce MX330 (GP108M, Pascal)** | Слабка: ~384 CUDA-ядра, **2 GB VRAM**, compute capability 6.1. |
| iGPU | Intel Iris Plus G1 (Ice Lake) | Не використовується. |
| Диск | `/` — 233 GB, **вільно ~11 GB (96 % заповнено)** | **Найжорсткіше обмеження.** Документація нижче містить розміри моделей саме для планування місця. |

### Про GPU: важливе уточнення

- Драйвер встановлено: `NVRM version: NVIDIA UNIX x86_64 Kernel Module 580.178.04`.
- Пристрої присутні: `/dev/nvidia0`, `/dev/nvidiactl`, `/dev/nvidia-uvm`.
- **Але `nvidia-smi` падає з `Failed to initialize NVML: Unknown Error`**, коли
  його запускає агентска оболонка. Причина майже напевно не в залізі:
  `CapEff` у цій оболонці дорівнює `0000000000000000`, тобто ефективних
  capabilities немає взагалі (їх знімає пісочниця DSH), а NVML потребує доступу
  до пристрою.
- **Що зробити, перш ніж вірити в GPU:** запустити `nvidia-smi` у власному
  терміналі (не через агента). Якщо там усе гаразд — GPU робочий, і 2 GB VRAM
  усе одно лишаються обмеженням.

**Практичний висновок:** планувати CPU-first. 2 GB VRAM не тягнуть
XTTS-v2/Chatterbox «комфортно», і точно не тягнуть IndexTTS-2 чи Higgs Audio v2.
Для виразного озвучення важкими моделями знадобиться або орендований GPU
(RunPod/Vast.ai класу), або зовнішній API — обидва варіанти вписані в
архітектуру як окремі адаптери.

## Програмне забезпечення

| Інструмент | Версія / стан |
|---|---|
| Python | 3.13.9 (у PATH). **Перевірено:** `/usr/bin/python3.11` — це CPython **3.11.16**, тобто потрібна версія вже є в системі. Також є 3.12 і 3.14 |
| `uv` | 0.9.17 (`~/.local/bin/uv`) — рекомендований менеджер залежностей |
| `poetry` | встановлено |
| `pipx` | встановлено |
| Docker | 29.8.1 (client), плагіни присутні |
| `torch` | **не встановлено** |
| ffmpeg | потребує перевірки перед етапом 1 (`ffmpeg -version`) |

### Чому 3.13 — це проблема і як її обійти

Частина TTS-бібліотек відстає від найновішого Python. Coqui-форки та деякі
залежності XTTS історично мають колеса лише до 3.11/3.12.

**Рішення:** для проєкту закріпити **Python 3.11** через `uv`. Перевірено — не
потрібно навіть завантажувати інтерпретатор, він уже є в системі:

```bash
uv venv --python 3.11     # → Using CPython 3.11.16 interpreter at: /usr/bin/python3.11
```

Це дає сумісність із найширшим набором TTS-рушіїв і не зачіпає системний
Python 3.13. Остаточний вибір версії зафіксовано в `docs/DECISIONS.md`
(ADR-002).

**Перевірено на практиці:** `.venv` на Python 3.11.16 створено, застосунок
запускається, `pytest tests/` проходить 4/4 тести (0.8 с). Каркас робочий.

### Рушії не вміщаються в одне середовище (перевірено)

`ukrainian-tts` і `chatterbox-tts` **не можна** поставити в один інтерпретатор.
Перевірено на uv 0.9.17 / CPython 3.11.16, найновіші версії обох:

| | `uk` (ukrainian-tts 6.0.2) | `expressive` (chatterbox-tts 0.1.7) |
|---|---|---|
| `numpy` | >=2.3.0 → **2.4.6** | >=1.24,<2 (\(py<3.13\)) → **1.26.4** |
| `torch` | >=2.8.0 → **2.12.1** | ==2.6.0 → **2.6.0** |
| `torchaudio` | >=2.8.0 | ==2.6.0 |

Це **два незалежні** конфлікти. Другий видно, лише якщо примусово зняти перший
(`--override numpy>=2.3.0`): резолвер одразу впирається в `torchaudio==2.6.0`
проти `>=2.8.0`. Тому «послабити numpy» проблему не вирішує.

Обидва набори **окремо** резолвляться бездоганно. Наслідок для роботи:

```bash
uv sync --extra piper       # MVP: Piper через OpenAI-сумісний шлюз (ADR-005)
uv sync --extra uk          # українська: in-process, numpy 2.x + torch 2.12
uv sync --extra expressive  # англійська: in-process, numpy 1.26 + torch 2.6
```

Спроба поставити `uk` і `expressive` разом тепер дає явну помилку
(оголошено в `pyproject.toml`, `[tool.uv] conflicts`), а не ребус про numpy:

```
error: Extras `expressive` and `uk` are incompatible with the declared conflicts
```

Якщо колись знадобляться **обидва одночасно** — це два середовища
(`UV_PROJECT_ENVIRONMENT=.venv-expressive uv sync --extra expressive`), а рушій
підключається через межу процесу (`openai_compat`, ADR-001). Деталі й
обґрунтування — ADR-012.

## Диск: план витрат

Вільно ~11 GB — цього **не вистачить** на «спробувати все». Орієнтовні розміри:

| Рушій | Розмір на диску |
|---|---|
| Piper, усі 5 українських голосів | ~0.44 GB (разом з усім каталогом Piper — ~2 GB) |
| Kokoro-82M (ONNX + voices) | ~0.4 GB |
| XTTS-v2 | ~2 GB |
| Chatterbox | ~3–4 GB |
| Fish Speech / OpenAudio S1-mini | ~2–4 GB |
| IndexTTS-2 | ~6–10 GB |
| Higgs Audio v2 | ~12 GB+ |
| `torch` + CUDA-колеса | ~2.5–7 GB |

Уже створене в проєкті: `.venv` на Python 3.11 з мінімальним набором
(fastapi, uvicorn, pydantic-settings, httpx, pytest) — **48 MB**. Повний набір
із `torch` буде на порядок більший.

**Рекомендація:** перед етапом 1 звільнити місце. Найбільші кандидати з
домашнього каталогу: `~/anaconda3` (15 GB), `~/backups` (9.9 GB),
`~/snap` (6.8 GB). Моделі тримати в `data/models/` на тому ж диску, але
керувати ними через `huggingface-cli`/`ollama`-подібний кеш, щоб можна було
видаляти непотрібні.

Якщо зовнішній носій є — краще винести `data/models` на нього через symlink і
вказати шлях у `.env` (`VOICE_STUDIO_MODEL_DIR`).

## Що з цього випливає для плану

1. **MVP будується на Piper** — 5 українських голосів, ~20–114 MB кожен,
   швидко на CPU, ставиться і сьогодні, ліцензія MIT.
2. **Виразність у MVP дає шар пост-обробки**, а не модель (Piper емоцій не вміє).
3. **Важкі виразні моделі — етап 3+**, і для них потрібен або орендований GPU,
   або зовнішній OpenAI-сумісний API. Архітектура це враховує з першого дня.
4. **Українська мова — головний ризик проєкту.** Деталі в `docs/RESEARCH.md`:
   більшість «виразних» моделей 2024–2026 українську не підтримують.
