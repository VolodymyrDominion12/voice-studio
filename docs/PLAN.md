# План проєкту

## Позначки

- `[x]` — зроблено й перевірено тестами;
- `[~]` — зроблено частково, поруч написано, чого саме бракує;
- `[ ]` — не зроблено.

---

## Принцип планування

Спочатку — **вертикальний зріз**: найтонший ланцюг «файл → текст → правка →
аудіо», але робочий від початку до кінця. Це дає змогу почути реальний
результат на першому тижні й перевірити головний ризик (якість українського
синтезу) до того, як вкладено роботу в UI.

Важкі виразні моделі — **не** в MVP. Спочатку те, що працює на наявному залізі.

## Етап 0 — Підготовка середовища

Передумова для всього. Без цього етапу етап 1 просто не запуститься.

- [ ] **Звільнити диск** до ≥40 GB. Зараз вільно ~11 GB, а тільки `torch` +
      моделі — це 5–12 GB. Кандидати: `~/anaconda3` (15 GB), `~/backups`
      (9.9 GB), `~/snap` (6.8 GB).
- [ ] **Перевірити GPU у власному терміналі** (не через агента):
      `nvidia-smi`. Драйвер 580.178.04 стоїть, але з-під пісочниці агента
      NVML падає. Треба знати напевно: 2 GB VRAM є чи ні.
- [ ] **Встановити нативний ffmpeg**: `sudo apt install ffmpeg` → дасть v6/v7 і
      `ffprobe`. Snap-версія 4.3.1 конфайнена і не годиться.
- [ ] **Python 3.11 через uv**: `uv python install 3.11`.
- [ ] **Підняти Speaches** у Docker, переконатися, що
      `curl -X POST .../v1/audio/speech` повертає WAV.
- [ ] Завантажити 5 українських голосів Piper (~440 MB разом).

**Критерій готовності:** команда `curl` до Speaches повертає коректний
український WAV-файл, і його чути як українську мову.

- [x] Детект кодування для `.txt` (UTF-8 → CP1251 → latin-1).

# дат і відмінювання років немає (num2words дає лише називний відмінок).
- [~] `services/normalize/uk.py`: числа, дати, скорочення, символи

- [x] Прибирання залишків розмітки, зноски, типографіка.
- [x] У редакторі — перемикач «вихідний / нормалізований / мій» і показ різниці.

**Шар виразу** (ADR-004)
- [x] `services/expression/profiles.py` — таблиця «емоція → просодія».
- [ ] Профілі Piper: `length_scale`, `noise_scale`, `noise_w`. (адаптер передає лише `speed`)
- [x] Паузи між абзацами та реченнями при склейці. Пауза після кожного
      сегмента береться з його `ProsodyPlan`, а на межі абзацу множиться
      на 1.5.
- [x] Корекція гучності сегмента за емоцією (`energy_db` застосовується до
      сегмента ДО глобальної нормалізації, тож динаміка зберігається).
- [x] Глобальна нормалізація до −18 LUFS (`pyloudnorm`).
- [x] UI: дропдаун емоції + повзунок інтенсивності на кожному блоці.

**Збірка книги**
- [x] Наскрізна нумерація розділів і пауза-роздільник: заголовки
      визначаються (у PDF — за розміром шрифту), кожен заголовок
      найвищого наявного рівня починає розділ, текст до першого заголовка —
      «Вступ» без номера, номер іде в метадані та в імена файлів. Будь-яка
      межа блоку дає довшу паузу (×1.5).
- [x] M4B/AAC із розділами — **без нативного ffmpeg**: кодує PyAV, колесо зі
      вбудованими бібліотеками FFmpeg (ADR-013). Мітки розділів беруться з
      таймлайну сегментів (тривалості + паузи), тож межі збігаються зі
      звуком, а не з оцінкою «скільки символів».
- [x] ID3-теги через `mutagen` (+ метадані MP4): назва, альбом, виконавець,
      жанр, рік, номер треку; у zip кожен розділ — окремий трек `N/M`.

**Критерій готовності:** завантажую PDF-книгу, бачу чистий розбитий на абзаци
текст, розмічую емоції на 20 абзацах, отримую M4B, де чутно різницю між
«радісним» і «сумним» абзацом, і гучність рівна по всій книзі.

## Етап 3 — Справжня виразність

Мета: перейти від «керованої просодії» до **гри моделі** там, де це можливо.

### 3.1 Головне: перевірити ZONOS2

Це найважливіший пункт усього плану після MVP, бо ZONOS2 — єдина знайдена
відкрита модель, яка дає **і вираз, і українську, і клонування голосу**
(Apache-2.0, нативна CPU-збірка).

- [ ] Звільнити ~10 GB і скачати `zonos2-q4_k.gguf` (4.92 GB) **явно**
      (`--quant q4_k`) — типовий перший запуск тягне Q6_K і ~7.1 GB.
- [ ] Підняти `zonos2-server` у режимі CPU (порт 1919), перевірити
      `/v1/audio/speech`.
- [ ] **Прослухати український текст і вирішити.** Це розвилка:
      - звучить добре → ZONOS2 стає рушієм «якісно», Piper лишається «швидко»;
      - звучить погано → ZONOS2 викреслюється, план MVP не змінюється.
- [ ] Виміряти real-time factor на 8 ядрах (`scripts/benchmark.py`).
- [ ] Якщо клонування голосу потрібне — прогнати референсний український
      семпл (ZONOS2 потребує `ffmpeg` лише для цього кроку).

> **Розвилка, а не пункт списку.** Доки ці три перевірки не пройдено, не варто
> перебудовувати нічого іншого. Мітигація вбудована: якщо ZONOS2 не підходить,
> втрачено лише час на завантаження, а MVP продовжує працювати як є.

### 3.2 Решта адаптерів

- [ ] `services/tts/zonos2.py` — або через `openai_compat` (у нього є
      `/v1/audio/speech`), або окремим адаптером, якщо контракт відрізняється.
- [ ] `services/tts/chatterbox.py` — Chatterbox Multilingual V3 (500M, 23 мови,
      `exaggeration` і `cfg_weight`). **Української серед 23 мов немає** — це
      рушій для англійських текстів; для англійської він значно легший за ZONOS2.
- [ ] `services/tts/ukrainian_tts.py` — прямий інтегральний адаптер
      (автонаголос, MIT, офлайн).
- [ ] Реалізація `capabilities()`: коли рушій уміє емоції, нативний шлях
      перекриває відповідні параметри шару виразу; решта (паузи, LUFS,
      структура) працює завжди.
- [ ] `services/tts/remote.py` — адаптер до зовнішнього API. Потрібен лише якщо
      ZONOS2 не пройде перевірку, а виразна українська потрібна негайно.
      **Опційно, вимкнено за замовчуванням**, ключі — лише в `.env`.
- [ ] GPU-профіль у `docker-compose`: для ZONOS2 це CUDA-варіант `zonos2.cpp`
      або Mini-SGLang; для решти — `latest-cuda`.
- [ ] Профілі якості в UI: «швидко (Piper, CPU)» / «якісно (ZONOS2, CPU/GPU)» —
      з чесною підказкою, скільки це триватиме.

**Критерій готовності:** є обґрунтована відповідь «так» або «ні» щодо ZONOS2
для української, зафіксована в `docs/RESEARCH.md`; англійський текст
озвучується з чутною емоцією нативною моделлю; перемикання рушія не вимагає
правок поза `services/tts/`.

## Що виміряти, а не вгадати

Ці числа в документації — **оцінки**, не вимірювання. Їх має замінити
`scripts/benchmark.py`:

1. **Real-time factor ZONOS2 (`q4_k`) на CPU** — критично для R2.
2. Real-time factor Piper (`medium` і `high`) на 8 ядрах.
3. Real-time factor `ukrainian-tts` (ONNX).
4. Розмір пікової RAM під час синтезу розділу (ZONOS2 `q4_k` — ~5 GB).
5. **Суб'єктивна якість української: ZONOS2 проти Piper проти `ukrainian-tts`** —
   сліпе прослуховування, бо це вирішує долю етапу 3.
6. Різниця в якості наголосу: Piper проти `ukrainian-tts` на 20 тестових
   реченнях із наголосами, що часто плутаються.
