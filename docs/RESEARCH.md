# Дослідження: чим озвучувати текст із виразом

Мета проєкту: локальне озвучення `.md` / `.pdf` / `.txt` українською (і за
потреби англійською) з **виразом**, на **відкритих** моделях, з вибором голосу.

Усе, що нижче, поділено на **перевірене** (з першоджерела — README, каталог
голосів, PyPI, HuggingFace API) і **оціночне**. Оцінки позначені явно. Там, де
даних немає, написано «не знайдено» — не здогадка.

Дата дослідження — момент створення документа. Ринок TTS рухається швидко:
перед вибором моделі варто перевірити статус проєкту ще раз.

---

## 1. Головний висновок

> **Знайшовся виняток, який змінює план: ZONOS2 (Zyphra).**
> Він підтримує українську, уміє вираз і клонування голосу, ліцензований
> Apache-2.0 і — головне — має офіційну **CPU-збірку**.
> Це єдина знайдена відкрита модель, яка закриває вимогу «вираз + українська».

### Чому це виняток, а не один із багатьох

Спершу перевірка дала похмуру картину. Її варто навести повністю — вона пояснює,
чому ZONOS2 вирізняється:

1. **XTTS-v2 підтримує 17 мов — української серед них немає.** Список із
   документації: ar, zh-cn, cs, nl, en, fr, de, hi, hu, it, ja, ko, pl, pt, ru,
   es, tr. Джерело: [Coqui TTS docs](https://coqui-tts.readthedocs.io/en/latest/models/xtts.html).
2. **Chatterbox Multilingual V3 — 23 мови, української немає.** Повний список з
   README: ar, da, de, el, en, es, fi, fr, he, hi, it, ja, ko, ms, nl, no, pl,
   pt, ru, sv, sw, tr, zh. Джерело:
   [resemble-ai/chatterbox](https://github.com/resemble-ai/chatterbox). Російська
   є, української немає.
3. **Робочих українських файнтюнів XTTS на HuggingFace не знайдено.** Пошук по
   API за `ukrainian tts`, `xtts ukrainian`, `uk tts` дав єдиний кандидат
   `mouseyy/xttsv2-ukrainian_220123`, у якому лежить **лише `config.json`, без
   ваг**. Тобто модель нефункціональна.

Серед «класичних» виразних моделей української не було **ніде**. ZONOS2 — перша
з-поміж перевірених, у якої вона є.

### ZONOS2: перевірені факти

| Властивість | Значення |
|---|---|
| Розробник | Zyphra |
| Розмір | ~7.6B параметрів, **MoE** (Mixture of Experts) |
| **Ліцензія** | **Apache-2.0** — і ваги, і GGUF. Комерційне використання дозволено |
| **Українська** | **Так** — Tier 3 |
| Вираз / якість | «expressiveness and quality on par with—or even surpassing—top TTS providers» |
| Клонування голосу | Так, «high-fidelity and naturalistic», in-process |
| Навчальні дані | 6+ млн годин багатомовного мовлення |
| **Пристрої** | **CPU**, CUDA, Apple Metal, Vulkan — з тих самих GGUF-файлів |
| OpenAI-сумісний API | **Так** — `/v1/audio/speech` у `zonos2-server` |

Джерела: [Zyphra/ZONOS2](https://huggingface.co/Zyphra/ZONOS2),
[Zyphra/ZONOS2-GGUF](https://huggingface.co/Zyphra/ZONOS2-GGUF),
[Zyphra/zonos2.cpp](https://github.com/Zyphra/zonos2.cpp).

**Розподіл мов за рівнями** (з картки моделі):

| Tier | Мови |
|---|---|
| 1 | English, Mandarin Chinese, Japanese |
| 2 | Korean, Russian, Italian, Portuguese, French, Spanish, Vietnamese, German, Hebrew, Dutch |
| 3 | Swedish, Hindi, Tamil, Telugu, Thai, Norwegian, Bengali, Tagalog, Arabic, Danish, Indonesian, Polish, **Ukrainian**, Romanian, Finnish, Hungarian, Lithuanian, Estonian, Slovak, Croatian, Latvian |

> **Українська — Tier 3, найнижчий рівень.** Це не дискваліфікує модель, але
> означає, що якість української найпевніше поступається англійській. Вимірювань
> якості саме для української не знайдено — **потрібне прослуховування, перш ніж
> будувати на цьому план.** Це головне, що лишилося перевірити.

**Чому це працює на цій машині.** `zonos2.cpp` — самостійний порт на ggml/GGUF:
увесь конвеєр (ECAPA-TDNN speaker encoder → MoE-бекбон → DAC-44kHz vocoder)
виконується нативним C++, який лінкується лише з `libggml` + `gguf`. **Без
Python, без PyTorch, без CUDA-специфічних ядер.** Є готові самодостатні збірки
під Linux x64 (CPU/Vulkan) — без інсталятора й без спільних бібліотек. Це
принципово: 2 GB VRAM на MX330 не потрібні взагалі.

### Розміри та ціна входу

| Файл | Розмір |
|---|---|
| `zonos2-q4_k.gguf` | **4.92 GB** — найменший |
| `zonos2-q5_k.gguf` | 5.82 GB |
| `zonos2-q6_k.gguf` | 6.79 GB |
| `zonos2-q8_0.gguf` | 8.54 GB |
| `zonos2-f16.gguf` | 15.34 GB |
| `dac.gguf` (vocoder) | 0.25 GB |
| `spk-encoder.gguf` | 0.02 GB |

Перший запуск `start-zonos2.sh` качає ~7.1 GB (Q6_K + DAC + speaker encoder).
Заявлено, що Q4_K звучить «within eval noise of F16».

**Реалістичний вибір для цієї машини — `q4_k`:** 4.92 GB + 0.27 GB допоміжних
≈ **5.2 GB**. RAM 19 GB це витримує із запасом. Але на диску вільно лише 11 GB,
тож етап 0 плану стає не бажаним, а **обов'язковим**.

`ffmpeg` потрібен ZONOS2 **лише для клонування голосу** (декодування
референсного аудіо). Звичайний синтез без нього працює.

### Що про ZONOS2 ще не перевірено

Це важливо, бо саме від цього залежить, чи стане він рушієм за замовчуванням:

- **швидкість на CPU.** README обіцяє «real time **on GPU**» — про CPU такої
  обіцянки немає. MoE на 8 ядрах може бути повільним. **Не виміряно.**
- **якість української.** Tier 3 — це класифікація покриття, а не оцінка якості.
  Суб'єктивна якість саме української **не підтверджена**.
- **якість клонування голосу українською** — не перевірена.
- чи покриває `/v1/audio/speech` у `zonos2-server` усі параметри, які
  використовує наш адаптер — не перевірено.

### Наслідок для архітектури

План не скасовується, а **доповнюється**. ZONOS2 стає рушієм за тим самим
інтерфейсом `TTSEngine` (ADR-001) — саме заради таких випадків ця абстракція й
закладалася.

Шар виразу (ADR-004) **не скасовується**, з трьох причин:

- ZONOS2 — модель на 5 GB; для швидкого перегляду й масового синтезу Piper
  залишається доцільнішим;
- паузи, структура книги, гучність (LUFS) і нормалізація тексту потрібні
  однаково для будь-якого рушія;
- якщо ZONOS2 на CPU виявиться надто повільним, шар виразу — це те, що
  залишиться працювати.

### 2.1 ZONOS2 — головний кандидат на «вираз + українська»

Загальні факти — у розділі 1. Тут — те, що потрібно для практичного запуску.

**Два способи запуску:**

| Шлях | Пристрій | Коли доречний |
|---|---|---|
| `zonos2.cpp` + GGUF | **CPU**, CUDA, Metal, Vulkan | **наш випадок** — 2 GB VRAM не потрібні |
| `Zyphra/ZONOS2` + Mini-SGLang | Linux x86_64 + NVIDIA CUDA | коли з'явиться потужний GPU |

`zonos2.cpp` дає два інструменти: `zonos2-server` (HTTP-сервер із
OpenAI-сумісним `/v1/audio/speech`, потоковим PCM, in-process клонуванням голосу
й браузерним UI, порт 1919) і `zonos2-cli` (офлайн-синтез).

**Вибір квантизації для цієї машини.** Заявлено, що Q4_K звучить «within eval
noise of F16», тож платити 8 GB за `q8_0` сенсу небагато. Але скрипт першого
запуску типово тягне **Q6_K + DAC + speaker encoder ≈ 7.1 GB**. Для диска з
11 GB вільного це забагато разом з іншими експериментами — **качати явно
`--quant q4_k`**.

**Точність реалізації.** README `zonos2.cpp` заявляє числову валідацію проти
PyTorch-референсу: speaker encoder і DAC-декодер — **біт-у-біт**, бекбон — до
косинусної схожості ≥ 0.9999. Це знімає типове занепокоєння щодо сторонніх
портів: результат має відповідати оригіналу.

**Ліцензійна перевага.** Apache-2.0 і на ваги, і на GGUF — на відміну від
XTTS-v2 (некомерційна) і F5-TTS (ваги CC-BY-NC). Це єдина виразна модель у
таблиці без ліцензійних застережень.

**Головне питання — швидкість на CPU.** README обіцяє реальний час **на GPU**;
про CPU такої обіцянки немає. MoE зазвичай активує лише частину експертів на
токен, що на користь CPU, але **це треба виміряти** — саме для цього існує
`scripts/benchmark.py`.

**Порядок дій:**
1. звільнити диск (етал 0);
2. скачати `q4_k` і підняти `zonos2-server` у режимі CPU;
3. **прослухати український текст** — це вирішальна перевірка, від неї залежить
   вся подальша архітектура;
4. виміряти real-time factor на 8 ядрах;
5. лише потім вирішувати, чи стає ZONOS2 рушієм за замовчуванням замість Piper.

### 2.2 Piper — основа MVP

Перевірено з каталогу `rhasspy/piper-voices` (`voices.json`, 177 голосів,
57 мовних варіантів):

| Голос | Якість | Розмір | Спікерів |
|---|---|---|---|
| `uk_UA-tetiana-high` | high | 114.2 MB | 1 (жін.) |
| `uk_UA-mykyta-high` | high | 114.2 MB | 1 (чол.) |
| `uk_UA-oleksa-high` | high | 114.2 MB | 1 (чол.) |
| `uk_UA-ukrainian_tts-medium` | medium | 76.7 MB | **3** |
| `uk_UA-lada-x_low` | x_low | 20.6 MB | 1 (жін.) |

Разом ~440 MB. **Це найдешевший вхід у проєкт:** працює на CPU, не потребує
GPU, не потребує torch (ONNX Runtime).

**Ліцензійний нюанс, який варто знати.** PyPI-пакет `piper-tts` v1.8.0
задекларовано як **GPL-3.0-or-later** (перевірено через PyPI API). Це наслідок
залежності від `espeak-ng` для фонемізації, а espeak-ng — GPL-3.0. Для
**локального приватного** застосунку це не має жодних наслідків. Для
розповсюдження бінарника — має, і тоді потрібно або прийняти GPL, або шукати
фонемізатор без espeak-ng.

### 2.3 `ukrainian-tts` (robinhad) — найкращий наголос

Перевірено з README і вихідного коду
([robinhad/ukrainian-tts](https://github.com/robinhad/ukrainian-tts), PyPI
`ukrainian-tts` v6.0.2, **MIT**):

- повністю офлайн, на ESPNET (FastPitch + HiFiGAN), є шлях через `espnet_onnx`;
- **5 голосів**: `Tetiana`, `Mykyta`, `Lada`, `Dmytro`, `Oleksa` — той самий
  набір, що в Piper;
- **автоматичний наголос** із пріоритетною чергою:
  `acute` → власний словник → словник → модель. Словник на базі
  `ukrainian-word-stress`, модель — `ukrainian-accentor`;
- **керування швидкістю мовлення**;
- заявлено роботу на Windows, macOS (x86/M1), Linux (x86/ARM) і навіть
  інференс на мобільних.

**Чому це важливо.** Для української неправильний **наголос** псує враження
сильніше, ніж відсутність емоції. Слухач пробачить рівне читання, але не
пробачить «замОк» замість «зАмок». Це робить `ukrainian-tts` не «ще одним
рушієм», а важливим інструментом контролю якості.

### 2.4 Chatterbox — найкращий «вираз», але не для української

Перевірено з README ([resemble-ai/chatterbox](https://github.com/resemble-ai/chatterbox)),
PyPI `chatterbox-tts` v0.1.7, **MIT**:

- Chatterbox Multilingual V3 — **500M параметрів**, 23+ мови;
- керування виразом через два параметри: **`exaggeration`** (інтенсивність
  подачі) і **`cfg_weight`** (наскільки сильно триматися референсу);
- рекомендації з документації: типово `exaggeration=0.5, cfg_weight=0.5`;
  для виразнішого читання — `cfg_weight` до ~0.3 і `exaggeration` до 0.7+;
  вищий `exaggeration` пришвидшує мовлення, і нижчий `cfg_weight` це компенсує;
- є **Single Language Pack** — окремі файнтюни на 6 пріоритетних мов;
- клонування голосу працює через референсний аудіофрагмент.

Це найкращий відкритий варіант для **англійської** виразної нарації. Для
української — не підходить.

### 2.5 Kokoro-82M — гарний, але не для нас

- **Apache-2.0**, 82M параметрів — найзручніша ліцензія з усіх;
- картка моделі на HuggingFace декларує `language: [en]`; реліз v1.0 (січ. 2025)
  дає **8 мов і 54 голоси** — української серед них немає;
- займав #1 у TTS Arena;
- PyPI `kokoro` вимагає Python `>=3.10,<3.13`; `kokoro-onnx` — `>=3.10,<3.14`
  (працює й на 3.13, без torch).

**Висновок:** чудовий вибір для англійської, непридатний для української.
Тримаємо як опційний рушій.

### 2.6 XTTS-v2 — колись стандарт, тепер глухий кут для нас

- 17 мов, **української немає**;
- ваги під **Coqui Public Model License** — обмеження на комерційне
  використання. Код форку `coqui-tts` (idiap) — MPL-2.0, але це ліцензія
  **коду**, не ваг;
- оригінальний пакет `TTS` (Coqui) **мертвий**: останній реліз 0.22.0 від
  грудня 2023. Живий форк — `coqui-tts` v0.27.5 (MPL-2.0), останній реліз
  січень 2026;
- потребує ~4 GB VRAM (дані з README openedai-speech).

### 2.7 Моделі, які варто відстежувати, але не брати в MVP

IndexTTS-2, Higgs Audio v2, Orpheus, Fish Speech / OpenAudio, Dia, Zonos,
Sesame CSM, VibeVoice — усі вони цікаві з погляду керування емоціями, але:

- жодна **не підтвердила** підтримку української;
- більшість вимагає 4–12 GB VRAM, чого на цій машині немає;
- розміри та вимоги до VRAM у таблиці вище — **оцінки**, не вимірювання.

Практичний шлях до них — через орендований GPU (RunPod / Vast.ai / Modal
класу) і той самий інтерфейс `TTSEngine`, без переписування застосунку.

## 3. OpenAI-сумісні TTS-сервери

### 3.1 `openedai-speech` — **застарів, не брати за основу**

Користувач назвав саме цей проєкт, тому це важливо сказати прямо. README
[matatonic/openedai-speech](https://github.com/matatonic/openedai-speech)
починається з:

> *«This software is mostly obsolete and will no longer be updated.»*

Останній реліз — **0.18.2 від 16.08.2024**. Автор сам рекомендує заміни:
Speaches, Kokoro-FastAPI, Auralis.

Що він умів (корисно знати, бо це фактично специфікація того, що нам потрібно):

- `/v1/audio/speech`, OpenAI-сумісний, без ключа;
- `tts-1` → **Piper** (швидко, CPU);
- `tts-1-hd` → **XTTS-v2** із клонуванням голосу, ~4 GB VRAM;
- `response_format`: mp3, opus, aac, flac, wav, pcm;
- `speed` від 0.25 до 4.0;
- потокова віддача під час генерації;
- **автовизначення мови** для XTTS;
- власні голоси через `voice_to_speaker.yaml`;
- regex-виправлення вимови через `pre_process_map.yaml` — **корисний патерн,
  який варто повторити в себе**;
- Python 3.9–3.11; «piper does not install on python 3.12 yet».

Два останні пункти — джерело ADR-002 (Python 3.11) і ADR-005 (заміна на Speaches).

### 3.2 Speaches — рекомендована заміна

Перевірено з README ([speaches-ai/speaches](https://github.com/speaches-ai/speaches),
документація [speaches.ai](https://speaches.ai/)):

- OpenAI-сумісний API; «усі інструменти й SDK, що працюють з API OpenAI, мають
  працювати й зі `speaches`»;
- TTS через **Piper** і **Kokoro**;
- STT через `faster-whisper` (бонусом — транскрипція, не потрібна для нашої
  мети, але нешкідлива);
- **динамічне завантаження й вивантаження моделей** — модель вантажиться під
  конкретний запит і вивантажується після простою. Для 19 GB RAM це важливо;
- **CPU і GPU**;
- розгортання через Docker / Docker Compose;
- позиціонується як «Ollama, але для TTS/STT-моделей».

**Рішення:** Speaches — основний TTS-шлюз. `openedai-speech` залишається
резервним варіантом і джерелом ідей для конфігурації голосів.

### 3.3 Kokoro-FastAPI

`remsky/Kokoro-FastAPI` — спеціалізований OpenAI-сумісний сервер саме під
Kokoro: високоякісний, зі змішуванням голосів. Обмеження те саме — Kokoro не
знає української. Тримаємо в резерві для англійської.

## 5. Нормалізація тексту — недооцінений важіль якості

Найдешевший спосіб підняти якість озвучення — **не** зміна моделі, а
нормалізація тексту. Модель не знає, як читати `2024`, `№5`, `10%`, `IT`,
`тобто` — і читає це літерами або як завгодно.

Перевірено: **`num2words` v0.5.14 підтримує `lang="uk"`** (у списку підтриманих
мов явно вказано `uk` (Ukrainian)). Це закриває числа, роки, порядкові
числівники.

Решта правил — власні (див. `docs/ARCHITECTURE.md`, розділ 2.2): символи
(`%`, `№`, `§`, `→`), латинські acronymи, залишки Markdown, зноски,
українська типографіка (`«»`, тире як маркер діалогу).

**Патерн, вартий запозичення:** `pre_process_map.yaml` з `openedai-speech` —
таблиця «regex → заміна» для виправлення вимови окремих слів. Додати такий
механізм у себе: він дає користувачу точку контролю без правки коду.

## 6. Аудіо-обробка та збірка

| Завдання | Інструмент | Ліцензія | Чому |
|---|---|---|---|
| Читання/запис WAV/FLAC/OGG | `soundfile` 0.14.0 | BSD-3 | без зовнішніх бінарників |
| MP3-енкодер | `lameenc` 1.8.4 | LGPL | **без ffmpeg** |
| Гучність EBU R128 (LUFS) | `pyloudnorm` 0.2.0 | MIT | стандарт для аудіокниг |
| ID3-теги | `mutagen` 1.48.1 | GPL-2.0 | стандарт де-факто |
| Склейка, паузи | власний код на `numpy`/`soundfile` | — | тривіально |
| M4B/AAC із розділами | `av` (PyAV) 18.1.0 | BSD-3 | колесо зі вбудованими бібліотеками FFmpeg — **без нативного ffmpeg** (ADR-013) |

**Ключове рішення (ADR-006):** базовий цикл працює **без ffmpeg**. Причина
конкретна й перевірена на цій машині: `ffmpeg` тут є **лише як snap** (v4.3.1),
нативних `/usr/bin/ffmpeg` і `/usr/bin/ffprobe` немає. Snap-версія конфайнена і
ненадійно працює з довільними шляхами, а v4.3 застарілий.

**Оновлення (28.09):** «потрібен ffmpeg» стосувалося лише M4B/AAC, і цю
потребу знято: PyAV робить і AAC, і розділи, і метадані, будучи звичайним
Python-колесом (ADR-013). Тож нативний `ffmpeg` лишається потрібним хіба що
для просунутого DSP — але й там спершу варто перевірити, чи не досить
наявних `numpy`/`soundfile`.

**Цільова гучність:** −18 LUFS для аудіокниги, −16 LUFS для подкасту.
Нормалізацію робити **глобально** після склейки, а не по сегментах, — інакше
знищується природна динаміка між тихою і гучною частинами.

**Заміна тону — обережно.** Це операція, яка найлегше звучить штучно. Тому:
темп — нативно через `length_scale` рушія (без артефактів), паузи — вставкою
тиші, і лише тон — через DSP, у межах ±2 півтони, і типово **вимкнено**.

## 7. Стек застосунку

| Шар | Вибір | Альтернативи | Чому так |
|---|---|---|---|
| Веб-фреймворк | **FastAPI** | Flask, Django | асинхронність (потрібна для SSE і паралельного синтезу), OpenAPI з коробки |
| Черга завдань | **власний asyncio-воркер + SQLite** | Celery, RQ, dramatiq, arq | Celery тягне Redis/RabbitMQ — зайвий сервіс для одного користувача (ADR-007) |
| Прогрес | **SSE** (`sse-starlette` 3.4.11) | WebSocket, polling | односторонній потік — саме SSE; працює через звичайний HTTP; polling марнує запити, WebSocket надлишковий |
| Стан | **SQLite (WAL)** | Postgres | один користувач, нуль адміністрування |
| ORM | **SQLModel** 0.0.47 | SQLAlchemy, сирий SQL | поєднує pydantic і SQLAlchemy, менше коду |
| Фронтенд | **Jinja2 + htmx + Alpine.js** | React/Vite, Gradio, Streamlit | нуль кроків збірки, один процес, стан на сервері (ADR-008) |
| Конфіг | **pydantic-settings** 2.15.0 | python-dotenv | типізація + валідація з коробки |
| Розгортання | **Docker Compose** | systemd | два сервіси, healthcheck, профіль GPU |

### Чому не Gradio / Streamlit

Обидва дають робочий прототип за годину. Але цільовий екран — це **список
абзаців, кожен із власним вибором голосу й емоції, власною кнопкою
прослуховування і статусом генерації**. У Gradio це перетворюється на боротьбу
з його моделлю компонентів, а в Streamlit — на боротьбу з моделлю перезапуску
скрипта, яка погано поєднується з фоновими завданнями.

**Правильне застосування Gradio/Streamlit тут — окремий внутрішній бенчмарк**
для порівняння голосів і моделей. Це справді зручно і не заважає основному UI.

## 9. Що перевірено, а що ні

### Перевірено з першоджерел

- каталог голосів Piper: 177 голосів, 57 мов, **5 українських**, їхні розміри
  та кількість спікерів (з `voices.json`);
- **ZONOS2**: Apache-2.0 на ваги й GGUF; українська в Tier 3 (20 мов Tier 3
  перелічено явно); ~7.6B MoE; розміри всіх GGUF-файлів з HF API (q4_k 4.92 GB …
  f16 15.34 GB, `dac.gguf` 0.25 GB, `spk-encoder.gguf` 0.02 GB); наявність
  офіційного `zonos2.cpp` з підтримкою CPU/CUDA/Metal/Vulkan, OpenAI-сумісним
  `/v1/audio/speech` і потоковим PCM; заява про біт-у-біт валідацію speaker
  encoder і DAC;
- список мов XTTS-v2: 17, **української немає** (з документації Coqui);
- список мов Chatterbox Multilingual V3: 23, **української немає** (з README);
- Kokoro-82M: Apache-2.0, базова картка — `language: en`;
- статус `openedai-speech`: **застарів**, останній реліз 0.18.2 (2024-08-16),
  із цитатою з README;
- можливості Speaches (OpenAI-сумісний, Piper + Kokoro, динамічне
  завантаження моделей, Docker, CPU/GPU);
- `ukrainian-tts`: MIT, 5 голосів, автоматичний наголос, офлайн;
- відсутність робочих українських ваг XTTS (пошук через HF API + вміст
  репозиторію-кандидата);
- версії, вимоги до Python і дати релізів ~25 Python-пакетів (PyPI API);
- `num2words` підтримує `lang="uk"`;
- стан машини: CPU/RAM/GPU/диск, Python 3.11–3.14, `uv`/`poetry`/`pipx`,
  Docker, **ffmpeg лише як snap**, `torch` не встановлено.

### Виміряно на цій машині (27.09, `scripts/benchmark.py`)

Перші **реальні** числа на цьому залізі. Замінюють оцінки, які стояли тут
раніше. Умови: 8 ядер CPU, `speaches-ai/piper-uk_UA-lada-x_low` у Docker,
повторів на голос — 3 (у дужках медіана, мін і макс).

| Що міряли | Голос | Аудіо | Стіна | RTF | Пікова RAM |
|---|---|---|---|---|---|
| Синтез 362 символів | `uk_UA-lada-x_low` | 16,8 с | 1,12 с | **0,068** (0,067–0,072) | 36 MB |
| Синтез 362 символів | `uk_UA-tetiana-high`¹ | 16,4 с | 1,46 с | 0,089 (0,077–0,091) | 36 MB |
| **Увесь конвеєр** 418 символів → MP3 | `uk_UA-lada-x_low` | 18,9 с | 2,45 с | **0,13** | 36 MB |

¹ Голосу `tetiana` у шлюзі **немає**: запит приймається (HTTP 200), але звучить
той самий `lada`. Числа для нього — це той самий голос під іншим імʼям.

**Що з цього випливає:**

* Piper на цих 8 ядрах іде **у ~15 разів швидше за реальний час** (RTF 0,068).
  Тобто 10-хвилинний розділ — це приблизно **40 секунд** синтезу, а не
  «від одиниць хвилин до 20», як оцінювалось раніше. Оцінка була песимістична
  в десятки разів.
* **Постобробка — 12–14 % часу конвеєра**: 0,31 с на склейку, LUFS і MP3 проти
  2,15 с на синтез. Тобто `soundfile` + `pyloudnorm` + `lameenc` (ADR-006,
  без ffmpeg) не є вузьким місцем.
* **RAM 36 MB** — це пам'ять процесу застосунку, а не моделі: модель живе
  в контейнері Speaches. Для порівняння рушіїв у процесі (`piper-tts`,
  `ukrainian-tts`) число буде іншим — їх тут не встановлено.
* Сегментація дала 6 сегментів на 418 символів при ліміті рушія 500 символів —
  сплітер ділить за реченнями, а не «набиває» ліміт.

**Не вдалося виміряти:** `piper-tts` і `ukrainian-tts` напряму (`--extra piper`
і `--extra uk` не встановлені в цьому `.venv`), ZONOS2 (`zonos2-server` не
запущено), Chatterbox (української не має). Скрипт чесно пише `SKIP` із
причиною — див. `data/benchmark/benchmark.json`.

### Не перевірено (оцінки — потребують вимірювання)

- **швидкість ZONOS2 на CPU** — найважливіше з неперевіреного. README обіцяє
  реальний час лише на GPU. Найдешевший спосіб перевірити — той самий
  `scripts/benchmark.py --engine zonos2` після `./start-zonos2.sh --cpu`;
- **суб'єктивна якість української в ZONOS2** (Tier 3 — це класифікація
  покриття, а не оцінка якості) та якість клонування голосу українською;
- чи покриває `/v1/audio/speech` у `zonos2-server` усі потрібні нам параметри;
- real-time factor `piper-tts` і `ukrainian-tts` **у процесі** (поза Docker):
  числа вище — для шлюзу Speaches, а не для прямого `--extra piper`;
- вимоги до VRAM для Chatterbox, IndexTTS-2, Higgs Audio v2, Orpheus;
- чи справді працює GPU (NVML падав із-під пісочниці агента; драйвер є);
- суб'єктивна якість українських голосів Piper проти `ukrainian-tts`
  (потрібне прослуховування, не читання документації);
- продуктивність `docling` проти `PyMuPDF` на реальних PDF;
- поведінка на книзі 1000+ блоків: механізми є (пагінація, серверні фільтри),
  вимірювання немає.

### Не знайдено

- робочий український файнтюн XTTS-v2 із вагами.

> **Виправлено під час дослідження.** Раніше тут стояло три пункти, серед них
> «будь-яка відкрита TTS-модель із одночасною підтримкою української та
> керування емоціями» і «відкрита модель із клонуванням голосу українською».
> **Обидва твердження хибні** — ZONOS2 задовольняє і перше, і друге. Залишено
> явно, щоб було видно, що початковий висновок перевірки був неповним.

## 10. Рекомендація

| Питання | Відповідь |
|---|---|
| **Головний кандидат на «вираз + українська»** | **ZONOS2** (`q4_k`, CPU-збірка через `zonos2.cpp`) — але **спершу прослухати й виміряти**, див. нижче |
| Чим озвучувати українською **гарантовано зараз** | **Piper** (голоси `uk_UA-*-high`) через Speaches + **`ukrainian-tts`** як рушій із найкращим наголосом |
| Чим озвучувати англійською **з виразом** | **Chatterbox Multilingual V3** (`exaggeration`, `cfg_weight`) — легший за ZONOS2 для англійської |
| Звідки взяти «вираз» для української | **ZONOS2 нативно**, якщо витримає перевірку; інакше — шар виразу (темп, паузи, гучність) |
| OpenAI-сумісний шлюз | **`zonos2-server`** для ZONOS2; **Speaches** для Piper. Обидва за одним адаптером `openai_compat` |
| Витяг тексту | `PyMuPDF` для PDF + `markitdown` для решти + `markdown-it-py` для `.md` |
| Черга та прогрес | asyncio-воркер + SQLite + SSE |
| Фронтенд | Jinja2 + htmx + Alpine.js |
| Python | **3.11** через `uv` — але **не** для ZONOS2: `zonos2.cpp` це нативний C++ і Python не потребує взагалі |
| Головний ризик | **Швидкість ZONOS2 на CPU** (не виміряна). Диск: 11 GB вільно проти ~5.2 GB моделі |

### Порядок перевірки, який знімає невизначеність

Не варто переписувати план під ZONOS2, доки не пройдено ці три кроки:

1. **Диск.** Звільнити місце — без цього крок 2 неможливий.
2. **Якість.** Скачати `q4_k`, підняти `zonos2-server` на CPU, синтезувати
   український текст і **послухати**. Якщо українська звучить погано — ZONOS2
   викреслюється, і план повертається до Piper + шар виразу.
3. **Швидкість.** Виміряти real-time factor. Якщо 10-хвилинний розділ
   синтезується годинами — ZONOS2 стає «якісним режимом на ніч», а не типовим.

Якщо крок 2 або 3 провалюється — план MVP не змінюється взагалі: Piper,
`ukrainian-tts` і шар виразу вже працюють. **ZONOS2 — це підвищення якості, а не
передумова.** Саме тому його підключення стоїть в етапі 3, а не в MVP.

Деталі рішень і відкинуті альтернативи — у `docs/DECISIONS.md`.
Покроковий план — у `docs/PLAN.md`.
