# Voice Studio — озвучення тексту з виразом

Локальний застосунок: завантажуєш `.md` / `.pdf` / `.txt` / `.epub` → отримуєш
чистий текст → редагуєш його у браузері → обираєш голос і емоцію → отримуєш
аудіо з виразом (не пласке читання), плюс зібраний MP3/M4B з розділами.

**Статус: документація + робочий каркас.** Реалізовано лише те, що потрібно,
щоб застосунок запускався: налаштування, healthcheck, каталог рушіїв і профілів
емоцій (`pytest tests/` → 4/4 проходять). Конвеєр обробки тексту й синтез —
попереду, див. [`docs/PLAN.md`](docs/PLAN.md).

## Головна ідея

Найважливіше рішення в проєкті — **не прив'язуватись до однієї TTS-моделі**.
Замість цього:

```
текст → нормалізація → сегментація → розмітка емоцій → адаптер рушія TTS → пост-обробка → збірка
```

«Вираз» народжується у двох місцях: (1) у самій моделі, якщо вона вміє емоції,
і (2) у шарі пост-обробки, який керує темпом, висотою, паузами та гучністю
для кожного сегмента. Другий шар працює з **будь-яким** рушієм — саме він дає
змогу почати на швидкій CPU-моделі сьогодні й перейти на важчу, не переписуючи
застосунок.

### Головна знахідка дослідження

Більшість «виразних» відкритих моделей українську **не** підтримують: XTTS-v2
(17 мов) і Chatterbox Multilingual V3 (23 мови) — обидва без неї, а робочих
українських файнтюнів XTTS не існує.

Але є виняток: **ZONOS2** (Zyphra, ~7.6B MoE) — підтримує українську (Tier 3),
уміє вираз і клонування голосу, ліцензований **Apache-2.0** і має офіційну
**CPU-збірку** (`zonos2.cpp`, нативний C++ без Python і PyTorch). Це єдина
знайдена відкрита модель, яка закриває вимогу «вираз + українська».

Він **не** в MVP: ~5 GB на диску (а вільно 11 GB) і, головне, не перевірено ні
якість української, ні швидкість на CPU. Тому ZONOS2 — це етап 3 із явною
розвилкою: спершу прослухати й виміряти, і лише потім будувати на ньому план.
Деталі — [`docs/RESEARCH.md`](docs/RESEARCH.md), розділ 1.

Деталі — у [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Швидкий старт (каркас працює вже зараз)

```bash
uv sync --extra dev            # база + pytest/ruff/mypy у .venv (Python 3.11)
cp .env.example .env
.venv/bin/python -m pytest tests/ -q                 # → 4 passed
.venv/bin/python -m uvicorn app.main:app --reload    # → http://127.0.0.1:8000/docs
```

Окремо — один рушій на середовище:

```bash
uv sync --extra piper        # MVP: Piper через OpenAI-сумісний шлюз (ADR-005)
uv sync --extra uk           # українська, in-process (ukrainian-tts)
uv sync --extra expressive   # англійська, in-process (chatterbox-tts)
```

`uk` і `expressive` **не сумісні** — це різні покоління `torch`/`numpy`, і
`uv` зупинить спробу поставити їх разом (ADR-012). Рушій, чий стек конфліктує з
поточним середовищем, підключається через `openai_compat`, а не імпортом.

Повний стек із TTS-сервером (після етапу 1):

```bash
docker compose -f docker/docker-compose.yml up -d
```
